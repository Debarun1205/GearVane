Open source AI harness, MIT licensed

Stop paying frontier prices for a typo fix.

Waypoint is an AI harness: it classifies what you asked for, runs the task through a tool-using agent loop with budgets and approvals, and picks the cheapest model tier that can do the job, escalating only when a cheaper model fails.

Download See it decide

Works on Windows, Linux, macOS, and Android - as a CLI, a VS Code extension, and a full IDE on desktop and Android alike. Android runs the app itself in a webview, where the IDE works over a device-local workspace. Bring your own keys, or run entirely on your own machine.

How it works

Three tiers, classified per request, with escalation on real failure rather than guesswork.

  1. 1

    Classify

    Keywords, files touched, error loops, and test failures are scored into a tier with a confidence you can inspect. Every decision shows its reasons.

  2. 2

    Run

    The cheapest tier that plausibly works runs first. Budget is checked before a single token is spent.

  3. 3

    Escalate only if it fails

    Failures feed back into the next decision. A local model that cannot do the job moves the task up a tier, bounded so an impossible task cannot burn every model in sequence.

Inside the harness

Routing is the engine; this is the machine around it. A tool-using agent loop, review gates, and four surfaces running the same code - a chat box with a model behind it is not a harness.

Routing engine

Classify, run, escalate only on real failure. Every decision shows its reasons, and the budget is checked before a single token is spent.

Agent loop with tools

Read, write, edit, search, and run commands through a tool-calling loop with sessions, context budgets, repeat detection, and cancellation.

Desktop IDE

File tree, tabs, an integrated terminal, workspace search, a Problems tab, and a model picker covering every configured provider.

Ask and Build modes

Ask answers questions without touching files. Build runs the loop with write tools, and every file the run created or changed lands in a Review list where it opens as a side-by-side diff.

Prompt-driven building

Describe an app and get a scaffold from real templates, preview the files, and write them to disk - from the CLI, VS Code, or the IDE.

Ghost text

Inline completions from a local model through Ollama, local only by design: completions never go to a hosted provider.

Budgets and approvals

Per-task, per-session, and per-day spend ceilings, gated operations that require an explicit approval, and a set of commands that never run at all.

Learns from outcomes

Recorded feedback retrains the learned classifier, which refines the heuristic choice and always defers to it when the two disagree.

Themes and onboarding

First-run onboarding, five dark themes, background ambience, accent colours, and a calm-motion mode. The look is stored per device, never in your config.

One engine, four surfaces: the CLI, the VS Code extension, the desktop app, and the Android build. Health checks probe your configured models from every surface that has a config.

Prefer to install from source?

The VS Code extension, the TypeScript CLI, and the Python package are all in the repository. 

git clone https://github.com/Debarun1205/Waypoint
cd Waypoint
npm install
npm run build --workspace @waypoint/core
npm run build --workspace @waypoint/cli
node packages/cli/dist/bin.js route --task "fix a typo"
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
pip install -e .
waypoint route --task "fix a typo"
cd apps/vscode-extension
npm install
npm run build
npx @vscode/vsce package
code --install-extension waypoint-0.3.0.vsix

These builds are not code signed. macOS Gatekeeper and Windows SmartScreen will warn on first launch, and the Android APK is debug-signed rather than Play-Store ready. Signing needs certificates that deliberately do not live in this repository. To get past the macOS warning, right-click the app and choose Open, or run xattr -d com.apple.quarantine /Applications/Waypoint.app. On Windows, choose More info then Run anyway.

About Waypoint

What this project is, how it is put together, and what it is not.

What it is

An AI harness built around a routing layer. It reads a request, classifies which tier can plausibly handle it, runs the cheapest one first, and escalates only when a cheaper tier actually fails - then hands the work to a tool-using agent loop whose changes you review as a diff. The point is not to be clever about which model to use; it is to stop paying frontier prices for work a free local model does perfectly well.

Why it exists

Teams buy a frontier model for everything by default, then discover that most of the traffic is typo fixes and lint cleanup. Waypoint makes the cheap path the default and makes the expensive path something you have to justify by watching it fail first.

How it is built

The engine is written in TypeScript with no runtime dependencies, which is what lets the same code run in Node, in the browser, in Electron, and inside an Android webview without a Python runtime present. A Python implementation is kept in the repository as the reference, and a parity test asserts both route identically.

What it is not

It is not a model and it does not host one. It is not a sandbox: the safety layer gates destructive operations and asks for approval, but it does not contain them. It is not production-ready, and the learned classifier has never been measured against real traffic. See the known limitations.

FAQ

What makes it a harness and not a chat app?

A chat app hands your text to one model. Waypoint classifies the task, routes it to a tier, runs it through a tool loop that can read, write, search, and run commands, gates destructive operations behind approvals, checks the budget before any token is spent, and shows the result as a diff you review. The chat box is one surface of that, not the product.

Do I need an API key?

Not to start. Install Ollama, pull a coder model, and Waypoint routes everything local with no key at all. Add a hosted key only if you want the mid and frontier tiers available.

Where are my keys stored?

In your shell environment, and nowhere else. Waypoint reads ANTHROPIC_API_KEY and similar variables, and never writes a credential to a config file, a log, or the dashboard. The desktop and Android apps additionally offer a Keys dialog whose vault lives only on that device, in its own storage; entries are sent solely to their own provider. Local model servers are never sent a key at all.

Does it work offline?

With only the local tier configured, yes. Nothing leaves your machine. You can verify this by checking that no hosted provider is present in your config.

How accurate is the routing?

The heuristic classifier is deterministic and shows its reasons, so you can argue with it. Accuracy depends on your keywords and file patterns, which you control. Once you have recorded enough outcomes you can train the learned classifier, which refines the choice but always defers to the heuristic on disagreement.

What happens when a local model fails?

The failure is fed back into the next routing decision. After the configured number of consecutive failures the task moves up a tier. Escalation is bounded, so a task that genuinely cannot be done will not march through every model in sequence.

Can I control the cost?

Yes. Set per-task, per-session, and per-day ceilings. Budget is checked before tokens are spent, so a task that would exceed the limit is refused rather than truncated. The app shows session spend as a live meter.

Can it push code or deploy for me?

The harness ships gating for those operations, but by default it will not act on your repository. Anything gated requires an explicit approval, and a set of commands such as rm -rf never run at all. Waypoint does not sandbox execution, so treat approvals as you would treat running the command yourself.

Which providers are supported?

Anything speaking the OpenAI chat completions API: OpenRouter, Groq, Together, DeepSeek, Mistral, xAI, Meta, LongCat, Gemini, vLLM, LM Studio, llama.cpp's server, LocalAI, GPT4All, and oobabooga's text-generation-webui, plus hosted OpenAI itself. Ollama has dedicated support, and the Anthropic Messages API is supported directly. Local servers need no key; hosted ones read theirs from the environment, never from the config file.

Why both a Python package and a TypeScript one?

The Python package came first and remains the reference implementation. It cannot be bundled into an Android app, so the engine was ported to TypeScript with the same behaviour and its own test suite. The CLI, the app, and the VS Code extension all use the TypeScript engine.

Is it production ready?

No. It is alpha. The router, escalation, budget gates, and provider clients are tested end to end. The learned classifier trains and predicts but has not been evaluated against real production traffic, which is the obvious next step.

Does the Android build include the IDE?

Yes. The APK runs the same renderer in a webview, and the IDE mounts over a device-local workspace kept in the app's own storage: editor, file tree, search, and the Ask-mode agent all work there. A webview has no shell, so there is no terminal, and file-changing builds stay desktop-only. The workspace README created on first launch says exactly this.
